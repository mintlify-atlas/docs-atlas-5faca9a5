# Quickstart

This guide will walk you through creating a complete Discord bot with event handlers and slash commands using mygourd.

<Note>
Make sure you've completed the [Installation](/installation) guide and have your Discord bot token ready.
</Note>

## Create your main file

Create a `main.ts` file in your project root. This is the entry point for your bot:

```ts main.ts
import { type } from 'arktype';
import { Client } from 'discord.js';
import { globAllRouters } from 'mygourd/routers';
import { login, useEnv } from 'mygourd/utils';

// Validate environment variables
const env = useEnv({
  BOT_TOKEN: type('string'),
});

// Create Discord client
const client = new Client({
  intents: ['Guilds', 'MessageContent', 'GuildMessages'],
});

// Automatically discover and register all routers
await globAllRouters(
  client,
  ['events/**/*.ts', 'interactions/**/*.ts'],
  import.meta.dir,
);

// Login with graceful shutdown
await login(client, env.BOT_TOKEN, () => {
  console.log('Shutting down!');
});
```

Let's break down what's happening:

1. **Environment validation** - `useEnv()` validates your environment variables using arktype schemas
2. **Client setup** - Create a standard Discord.js client with the intents you need
3. **Auto-discovery** - `globAllRouters()` finds and registers all event handlers and interactions
4. **Graceful login** - `login()` handles the login process and graceful shutdown on SIGINT/SIGTERM

## Create your first event handler

Create an event handler to know when your bot is ready. Create `events/ready.ts`:

```ts events/ready.ts
import { createEventRouter } from 'mygourd/events';

export const readyEvents = createEventRouter({
  clientReady: (client) => {
    console.log(`✓ Bot is ready! Logged in as ${client.user.tag}`);
  },
});
```

mygourd provides full type safety for event handlers. The `clientReady` event automatically types the `client` parameter.

<Tip>
You can export multiple event routers from the same file. Each router will be automatically registered.
</Tip>

## Add a message event handler

Let's add another event handler to respond to messages. Create `events/messages.ts`:

```ts events/messages.ts
import { createEventRouter } from 'mygourd/events';

export const messageEvents = createEventRouter({
  messageCreate: async (message) => {
    // Ignore bot messages
    if (message.author.bot) return;
    
    // Simple ping response
    if (message.content.toLowerCase() === '!ping') {
      await message.reply('Pong! 🏓');
    }
  },
});
```

## Create your first slash command

Slash commands are the modern way to interact with Discord bots. Create `interactions/commands/ping.ts`:

```ts interactions/commands/ping.ts
import { SlashCommandBuilder } from 'discord.js';
import { createInteractionRouterCommand } from 'mygourd/interactions';

export const pingCommand = createInteractionRouterCommand({
  definition: new SlashCommandBuilder()
    .setName('ping')
    .setDescription('Check if the bot is responsive'),
  handler: async (interaction) => {
    const latency = Date.now() - interaction.createdTimestamp;
    await interaction.reply({
      content: `🏓 Pong! Latency: ${latency}ms`,
      flags: 'Ephemeral',
    });
  },
});
```

The `handler` function receives a fully-typed interaction object that matches your command definition.

## Add a command with options

Let's create a more complex command with user input. Create `interactions/commands/echo.ts`:

```ts interactions/commands/echo.ts
import { SlashCommandBuilder } from 'discord.js';
import { createInteractionRouterCommand } from 'mygourd/interactions';

export const echoCommand = createInteractionRouterCommand({
  definition: new SlashCommandBuilder()
    .setName('echo')
    .setDescription('Repeat a message back to you')
    .addStringOption((option) =>
      option
        .setName('message')
        .setDescription('The message to echo')
        .setRequired(true)
    ),
  handler: async (interaction) => {
    const message = interaction.options.getString('message', true);
    await interaction.reply({
      content: `You said: ${message}`,
    });
  },
});
```

## Run your bot

<Steps>

<Step title="Make sure your .env file has your bot token">
  ```bash .env
  BOT_TOKEN=your_discord_bot_token_here
  ```
</Step>

<Step title="Run your bot with Bun">
  ```bash
  bun run main.ts
  ```
  
  You should see your bot come online and log the ready message.
</Step>

<Step title="Test your commands">
  In Discord, type `/ping` or `/echo` to test your slash commands. The commands should appear in the autocomplete menu.
</Step>

</Steps>

## Project structure

Your project should now look like this:

```
my-discord-bot/
├── events/
│   ├── ready.ts        # Ready event handler
│   └── messages.ts     # Message event handler
├── interactions/
│   └── commands/
│       ├── ping.ts     # Ping command
│       └── echo.ts     # Echo command
├── main.ts             # Entry point
├── .env               # Environment variables
└── package.json       # Dependencies
```

## Multiple routers per file

You can export multiple routers from a single file. Each router will be registered independently:

```ts events/logging.ts
import { createEventRouter } from 'mygourd/events';

export const readyLogger = createEventRouter({
  clientReady: () => {
    console.log('Bot is ready!');
  },
});

export const anotherReadyLogger = createEventRouter({
  clientReady: () => {
    console.log('Bot is ready, but in a different router!');
  },
});
```

Both routers will be called when the `clientReady` event fires.

## Handling intents

Different Discord events require different intents. Here are common intents you might need:

```ts main.ts
const client = new Client({
  intents: [
    'Guilds',                    // Guild create/update/delete events
    'GuildMessages',             // Message events in guilds
    'GuildMembers',              // Member join/leave events
    'GuildVoiceStates',          // Voice state updates
    'MessageContent',            // Access to message content
    'DirectMessages',            // DM events
  ],
});
```

<Note>
Some intents like `MessageContent`, `GuildMembers`, and `GuildPresences` are privileged and must be enabled in the Discord Developer Portal under your bot's settings.
</Note>
